# 성경쓰기

성경을 **키보드로 옮겨 적으면서** 읽는 도구. 손글씨 필사 앱이 아니라 워드 치듯 타이핑한다.
한 절씩 원문을 보며 따라 치고, 틀린 글자는 그 자리에서 표시되고, 쓴 만큼 통독 진도가 쌓인다.

빌드 도구 없음. 서버 없음. 외부 라이브러리 없음. `index.html`이 전부다.

## 본문은 직접 넣어야 합니다

이 앱에는 성경 본문이 들어 있지 않다. 개역개정·새번역 같은 번역본은 저작권물이라
함께 배포할 수 없기 때문이다(법적 판단이 필요한 사안은 전문가 확인을 권장합니다).

넣는 방법은 두 가지다.

1. **붙여넣기** — 쓰시던 성경 앱·사이트에서 한 장을 복사해 `본문` 화면에 붙여넣는다.
   절 번호가 있든 없든, 한 줄에 여러 절이 붙어 있든 알아서 쪼갠다. 쪼갠 결과를
   미리보기에서 확인하고 고칠 수 있다.
2. **파일** — 들여온 본문을 `파일로` 버튼으로 내보내 `data/bible/` 폴더에 두면
   다음부터 앱이 알아서 읽는다. 브라우저 저장소가 비워져도 복구된다.

`data/bible/*.js`는 `.gitignore`에 들어 있다. **본문 파일을 저장소에 커밋하지 말 것.**
개인적으로 쓰는 것과 공개 저장소에 올리는 것은 다르다.

## 웹 주소로 여세요

`index.html`을 더블클릭해서 열면(=`file://`) 크롬·엣지는 IndexedDB를 막는다.
앱은 그 경우 축소 모드로 돌지만 **창을 닫으면 쓴 글이 사라진다.**
깃허브 페이지 등 `https://`로 올려서 쓰는 걸 전제로 한다. 서비스워커도 그때만 등록된다.

### 판정 엔진이 하는 일

한글은 "한"을 치려면 ㅎ → 하 → 한 을 거친다. 조합 중인 글자를 틀렸다고 칠하면
정상 타이핑 내내 화면이 빨갛게 깜빡인다. 그래서:

- **확정된 글자**는 음절을 그대로 비교한다.
- **조합 중인 글자**만 자모 접두사로 비교하고, 원문을 **2글자 더 내다본다.**
  원문이 "가나"일 때 ㄱㅏㄴ은 IME가 "간"으로 만든다(다음 초성이 앞 글자 받침으로 붙는다).
  한 글자만 견주면 오타로 뜨고, 두 글자를 견주면 조용히 넘어간다.
- 조합이 끝났는데 부분만 맞으면(원문 "한", 입력 "하") 그때는 오타다.

정확도는 `오타로 바뀐 순간`만 센다. 조합 중 상태는 절대 오타로 세지 않는다.
타수는 키를 세지 않고 `원문 자모 수 / 경과 분`으로 낸다(한컴 타자연습과 같은 정의).

## 개발

테스트는 브라우저에서 연다. `file://`에서는 `<script src>`가 막히는 환경이 있어
확인용 번들을 만들어 열면 된다.

```bash
sh dev/bundle.sh dev/hangul-test.html > dev/_bundle.html
```

- `dev/hangul-test.html` — 자모·정규화·판정 엔진. **두벌식 IME를 흉내내어**
  문장을 한 타씩 끝까지 치면서 오타 표시가 한 번도 뜨지 않는지 검사한다.
- `dev/parse-test.html` — 붙여넣기 파서. 표본에는 저작권 때문에 실제 성경 대신
  같은 꼴로 지어낸 문장을 쓴다(파서가 보는 건 내용이 아니라 형태다).
- `dev/ime.js` — IME 시뮬레이터. 테스트 전용이며 배포 파일이 아니다.

실제 기기에서 손으로 확인해야 하는 것:

- 안드로이드 GBoard 한국어 조합 단위(`compositionupdate.data`가 1음절인지 어절 전체인지)
- iOS 사파리에서 `-webkit-text-fill-color: transparent` + `caret-color`
- 키보드가 올라온 상태에서 입력창이 가려지지 않는지
